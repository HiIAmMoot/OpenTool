Lights attached to scenery now bake, CPU-only bakes take about a sixth of the time, and the app warns before a bake that may run out of memory.

## Download

`OpenTool-v0.2.1-windows-x64.zip` holds `OpenTool.exe` and `OpenTool-cli.exe`, as in 0.2.0. Unzip it and run `OpenTool.exe`. The only thing to install is [Blender 5.2](https://www.blender.org/download/) or newer. The zip is TODO MB (0.2.0: 187.6 MB).

## Scenery lights

- Static lights attached to scenery, such as torches, now light the level the way tool lights it. Dynamic lights never bake. Both point lights and spot lights work.
- The lamps are real Cycles lights, so a surface facing the lamp gets more light than one at a slant. Tool leaves that out for point lights. We compared against tool's own bakes of a test lamp and, close to the lamp, the light OpenTool adds matched tool's to within about 1 percent. Tool's limit on how far a lamp reaches is kept.
- A lamp's own model does not shadow it. Light bounces off surfaces as it does for the sun.
- A level with very many lamps is baked in extra batches and the results are added together, so it is never refused.
- Lighting changes on maps that have static scenery lights. On the stock maps checked, only the torches on b40 and c40 and one fog light on b40 give off light; c40 has up to 46 lamps in one BSP. TODO: stock c40 bake time and how it compares with tool (still being measured).
- Cycles' sample clamp is now off for every bake, so bright lights are not cut short. On maps without scenery lights this is the only change, and it can make very bright emitters bake brighter.

## Ignore normals

- Shaders with the "ignore normals" flag are now lit the way tool lights them, instead of like ordinary shaders.
- Advanced has a new "Ignore-normals lighting" choice: Enhanced or Traditional. Traditional matches tool. Enhanced goes further: flagged surfaces gather sun and bounced light from both sides without the usual fall-off by angle, and light reflected off them reaches their neighbours. Enhanced is the default, so lighting changes on levels that use these shaders. `ignore_normals_mode` sets it in a settings file.
- "32-bit lightmaps" moved into Advanced. Both settings stay as you set them whichever preset you choose, and changing them does not switch the preset to Custom.
- Calibration always uses Traditional, because it fits against tool.

## Faster CPU bakes

- The per-vertex light now runs as compiled, multi-threaded code on the CPU. Against the old method on the same computer, the per-vertex pass is 10 to 13 times faster: Putput 399 s to 39 s, Rat Race 111 s to 10 s, Blood Gulch 160 s to 12 s.
- Whole CPU-only bakes at 0.2.0's settings: Rat Race 181 s to 31 s, Rat Race at Normal 57 s to 23 s, Putput 394 s to 69 s. These were timed with Ignore-normals lighting set to Traditional; Enhanced was not timed.
- The first CPU bake on a computer compiles the pass once, which took 52 to 83 s on ours. After that it loads from a cache in `%LOCALAPPDATA%\OpenTool\numba-cache` in under a second. TODO: confirm the cold-compile figure to quote (the plan said about 46 s; the ledgers record 52, 72 and 83 s).
- The results agree with the old method to within 0.13 percent on every vertex we compared. They are not bit for bit the same.
- GPU bakes are unchanged.

## Memory

- Before a bake the app estimates how much memory it needs and shows it against the free memory: "Needs about N GB". It updates when you change the BSP, scenario, texel density or Max resolution.
- If the bake may not fit, the app and the CLI warn and let you go on at your own risk. The app asks before it starts. Nothing is refused for memory.
- If Blender does run out of memory, the bake stops with a message that says so, instead of a Blender crash and a traceback.
- Texel density is now a dropdown with 1, 2, 4, 8, 12, 16, 24 and 32. A value from a settings file outside the list is kept and shown.
- Max resolution shows a hint at 2048 and 4096 that bigger pages need more memory. One full 4096 by 4096 page is estimated at about 43 GB. That is an estimate, not a measurement. Pages reached about 11.6 GB at 2048 on Blood Gulch and Putput.

## Device rows

- Before a bake, the app shows where the page bake, the vertex pass and the denoiser will run. After it, the rows show what ran.
- The GPU denoiser is tested when the app starts, so on an AMD card the denoiser shows as CPU from the start instead of after the first bake.

## Fixes

- Scenery placed with an origin offset now shadows in the right place. Before, the shadow was off, and the error turned with the object's rotation. Blood Gulch, Rat Race and Putput place no such scenery; Monaco's tires are an example that does.
- Cut-outs on environment shaders now read the alpha of the bump map, which is what the game tests. Monaco's fences no longer bake solid, and `teleporter_base` is no longer cut out. Alpha grates and tree fillers such as b30's and a30's gain the holes the game draws.
- Tag references are written with backslashes.
- A finished bake could fail at the very end while removing the denoiser's temporary folder ("file in use" on Windows). It no longer can.

## Known limits

- Windows only.
- Tested on an NVIDIA RTX 4060 laptop GPU and an AMD Radeon 680M. Intel GPUs are untested.
- The denoiser runs on the CPU on AMD, because Open Image Denoise's HIP device did not open on the Radeon 680M. The app shows it up front and in the warnings.
- The app is not signed, so Windows SmartScreen may warn the first time. Choose More info, then Run anyway.
- The memory figure is an estimate fitted to bakes of three stock maps, and it only warns. It was fitted before Enhanced ignore-normals existed, so a bake of a level with large flagged areas may need more than it says.
- Scenery lights differ from tool in a few ways: lamps are physically accurate where tool's point lights are not, a lamp's own model casts no shadow on it, and light does not wrap round curved surfaces that turn away from a lamp as the sun's does. Scenery that is animated in game is placed in its default pose.
