Lightmaps are now more accurate, CPU-only bakes are about six times faster, and the app warns before a bake that may run out of memory.

## Download

`OpenTool-v0.2.1-windows-x64.zip` holds `OpenTool.exe` and `OpenTool-cli.exe`. Unzip it and run `OpenTool.exe`. The only thing to install is [Blender 5.2](https://www.blender.org/download/) or newer. The zip is TODO MB.

## New

- Static lights attached to scenery (like torches) now light the level. They bake as Cycles lights calibrated against tool's own bakes, but with bounces. Lighting changes on maps with static scenery lights, which among the stock maps are b40 and c40.
- Shaders flagged "ignore normals" get their own lighting. Advanced has an "Ignore-normals lighting" choice. Traditional matches tool's method. Enhanced lights flagged surfaces from both sides and lets them pass light on to their neighbours.
- The per-vertex pass runs as compiled code on the CPU when there is no GPU available. Without a GPU, Rat Race now bakes in 31 s instead of 181 s, and Putput in 69 s instead of 394 s. The first CPU bake compiles it once, which takes about a minute. GPU bakes are unchanged.
- The app shows how much memory a bake needs and warns if it may not fit.
- Page bake, vertex pass & denoiser show which device will be used (cpu or gpu)
- Texel density is a dropdown from 1 to 32. 
- Added 32-bit lightmaps option, visible under Advanced.

## Fixes

- Cut-outs on environment shaders read the bump map's alpha instead of the base map alpha (which was wrong).
- Scenery with an origin offset now shadows in the right place.
- Tag references are always written with backslashes.
- A finished bake could fail while removing the denoiser's temporary folder ("file in use").

## Known limits

- On my AMD integrated graphics the denoiser runs on the CPU, but the app shows this before the bake.
- The memory figure is an estimate.
